### Data Stored Locally

Application data required for ordinary operation is stored locally on the device:

- **Reflections:** Free-text journal entries associated with a date and creation time, and temporary reflection drafts kept while you are writing
- **Gratitude items:** Free-text gratitude entries associated with a date and creation time
- **Mood entries:** Optional mood-scale values and/or named mood labels you choose, with date and creation time
- **Mood statistics (computed on device):** Averages, trends, coverage, emotion occurrence counts, best/worst day highlights, and related summaries derived from your mood entries
- **Reminder preferences:** Which optional reminders are enabled (Reflections; Gratitude; Mood morning / day / evening) and the times you choose
- **App lock settings:** Whether app lock is enabled; a salted cryptographic hash of your optional PIN (not the PIN itself); related salt; and whether biometric unlock is enabled
- **App preferences:** Language (including system default); theme (light / dark / system); start screen; date and time display formats; mood color palette; and backup choices (including the backup folder selected, if any)

This information is stored in a local SQLite database and in app-private SharedPreferences. The app does not transmit it to Basic Organizer or to any server operated by Basic Organizer. Optional backup and export features can create copies of some of this data outside the device, as described below.

### Optional reminders

Reminders are optional. Each reminder type can be turned on or off in Reminders, and each starts **off** by default. Notifications appear on screen only if the corresponding reminder is enabled **and** the device’s notification permission / system notification settings also allow them.

When a reminder is enabled and the system allows notifications, the app may schedule a local inexact alarm for the chosen time, subject to Android’s background scheduling and device power-management behavior. Reminder types include:

- Reflections
- Gratitude
- Mood (morning, day, and/or evening)

Notification titles name the relevant section (Reflections, Gratitude, or Mood). Notification bodies are short generic prompts (for example, to write reflections, to note gratitude, or to check how you are feeling). They are **not** filled with the text of your journal entries, mood values, or emotion labels.

On Android 13 and later, the app declares the `POST_NOTIFICATIONS` permission. When you save reminders with one or more types enabled, the app may request that permission if it has not already been granted. If permission is denied, or if notifications are blocked in system settings, reminders may not appear even though the in-app switches remain on.

After a device restart, app update, or time / timezone change, the app may reschedule enabled reminders locally. Delivery can be affected by Do Not Disturb, battery optimization, Doze mode, manufacturer-specific power management, missing permission, or other system settings outside the developer’s control. Reminders use inexact scheduling and are not guaranteed to fire at the exact chosen minute, or at all.

Tapping a notification opens the app to the relevant section. The current version is not designed to send notification events to advertising, analytics, or crash-reporting services.

### Optional app PIN (app lock)

An optional numeric PIN may be set in Settings. When enabled, the app may require the PIN (or, if you enable it, device biometrics) when the app is opened or returned to from the background.

- The PIN itself is not stored by the app. The app stores a salted cryptographic hash of the PIN in app-private preferences.
- The hash is intended to avoid keeping the PIN in readable form. It is **not** intended to resist large-scale offline guessing: a short numeric PIN has few possible values, so anyone who obtains the stored hash and salt from the device should be assumed capable of recovering the PIN. The PIN should not be reused from any other service.
- If biometric unlock is enabled, authentication is handled by Android’s biometric system. The app receives only a success/failure result and does not access fingerprint, face, or other biometric templates.
- The PIN is a convenience lock for casual access on the device. It is not a guarantee of security against a determined attacker, rooted or compromised devices, backups, forensic tools, or physical access to an unlocked device.
- The PIN hash and salt are stored in the app’s preference file for lock settings. The current Google Backup path described below is designed to include the journal database and backup preference file only, and the current folder backup JSON is designed to include journal entries only — not the PIN hash. A forgotten PIN therefore cannot be recovered from those backups either.
- Forgotten PINs cannot be recovered by the developer. Clearing app data or uninstalling (which can result in data loss if no suitable backup of journal content exists) may be required to regain access.

### Optional backups

Backup is optional. In the app, both Google Backup and folder backup are **off by default** until switched on in Backup & Restore. Either option, both, or neither may be used.

Because journal content may include sensitive personal or emotional well-being information, users should consider carefully whether to enable backups and where folder backup files are stored.

#### Google Backup

- The app allows Android backup (`allowBackup`). A custom full-backup agent is designed to include journal data only when the in-app Google Backup option is switched on; if that option is off, the agent is designed to back up nothing through that path. (Key/value backup APIs are unused.)
- Journal data is added to Google Backup only when the Google Backup option is switched on in Backup & Restore and Google Backup is enabled in device settings. When included, that backup is designed to contain:
  - The journal SQLite database (reflections, gratitude items, and mood entries)
  - Backup preference settings (such as opt-in flags and, if folder backup was configured, the chosen folder location and related backup state)
- App personalization preferences (for example theme, language, date/time formats, start screen, mood palette) and app-lock settings (PIN hash/salt, biometric switch) are **not** included in the current Google Backup include list.
- That backup is handled by Google under Google’s Privacy Policy, not by the Basic Journal developer. The developer does not receive, access, or host that data. Google operates and controls its backup service, including its applicable security, retention, restoration, and deletion mechanisms. Those practices are governed by Google’s applicable policies and settings. Basic Organizer does not control those mechanisms.
- The option may be turned off in the app at any time. Turning it off stops the app from adding journal data to later backups and asks Android to process the changed backup state. A previously stored copy may remain until Google processes a later backup or the user deletes the device backup in Google account or device settings; the app cannot verify or control when Google removes it.
- The app’s backup configuration applies to backup mechanisms that use the Android backup system. The in-app Google Backup switch does **not** control every copy path on Android. In particular, Android’s separate **device-to-device transfer / phone migration** path (when you set up a new phone from an old one) is governed by the app’s device-transfer rules, not by the Google Backup switch. In the current version those rules allow the journal database and backup preference file to be included in such a transfer even if Google Backup is switched off in the app. Device manufacturers may also provide their own transfer or migration tools, whose behavior can vary by device and Android version.
- The developer does not control third-party device backup, migration, cloning, synchronization, restoration, or transfer mechanisms. Such mechanisms may copy, retain, modify, omit, or otherwise process application data independently of the app’s own backup settings. Their operation is governed by the applicable device manufacturer, operating system, or service provider.

#### Folder backup

- Only when switched on and a folder is chosen with the system file picker (for example a folder on the device, or in the user’s own cloud storage).
- When folder backup is enabled, a backup file is written promptly, then about once a day (the schedule may be delayed if the battery is low). The app attempts to keep the **5 most recent** backup files it created in that folder and may delete older backup files it created when a new one is written.
- The backup file is a plain-text JSON file containing reflections, gratitude items, and mood entries (including mood scale values and emotion labels where present), plus backup metadata (such as format version, app identifier, and export time). App preferences, reminder settings, language, theme, and PIN hash/salt are **not** currently included in the folder backup JSON. The folder backup file is **not encrypted by the app**. Anyone with access to that folder can read its contents, which may include sensitive personal or emotional well-being information. The folder should be chosen accordingly.
- Files are written only to the location chosen by the user. The developer does not receive, access, or host those files. If the folder is in a cloud service, that service’s own privacy policy and terms apply.
- Restoring from a folder backup **replaces** the journal data currently in the app.
- Folder backup may be turned off at any time. Turning it off stops further automatic writes. Existing backup files remain in the folder until the user deletes them.

- **WAKE_LOCK, FOREGROUND_SERVICE, and ACCESS_NETWORK_STATE:** Added by AndroidX WorkManager’s scheduling infrastructure. Basic Journal uses WorkManager for optional folder backups, with a battery-not-low constraint. The current backup worker does not require a network connection and does not directly start a foreground service.
- **A package-specific signature permission:** Added by AndroidX to protect internal broadcast receivers from other applications. It grants no access outside the app.

The presence of any of these permissions does not mean that Basic Journal uploads journal data to the developer or to a developer-operated server.

The app’s application code is designed not to upload journal data to Basic Organizer or a developer-operated server. As supporting evidence of that design, the app does **not** declare the Android `INTERNET` permission.

Choosing a backup folder or exporting a file uses Android’s system file picker, which grants access only to the location selected. The app does not request broad storage access. Opening an external link (for example the developer page on Google Play) uses the system to launch another application; it does not grant this app network access for uploading journal data.

This list describes the current version. Permissions contributed by bundled components can change when those components are updated; the permission list shown by Google Play or by the device at install time is authoritative for the version being installed.
